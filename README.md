# Finance Fieldbook

경제·금융·재무설계·법률의 개념과 원리를 읽는 참고서입니다. 사용자가 정리한 원자료의 범위와 아이디어를 바탕으로 설명과 예시를 새로 작성했습니다.

## 실행

```powershell
python scripts/build.py
python -m http.server 8765 --bind 127.0.0.1 --directory dist
```

http://127.0.0.1:8765 에서 확인합니다. 앱은 JSON을 읽으므로 HTTP 서버가 필요합니다. `dist/finance-guide-print.html`은 직접 열거나 브라우저에서 인쇄/PDF로 저장할 수 있습니다.

## 구성

- 첫 화면에는 경제 / 금융·투자 / 재무설계 / 법률·윤리의 네 분야만 표시합니다.
- 개념 사전은 분야·주제별 카드와 제목·본문 검색을 제공합니다. 전체 검색은 Ctrl/Cmd K로 엽니다.
- 109개 개념마다 네 문단의 서술형 본문으로 정의, 작동 원리, 사례와 해석을 설명합니다. 본문은 접지 않고 이어서 표시하며 공식·구조를 함께 배치합니다.
- 북마크와 관련 개념 링크를 제공합니다. 복습 체크, 진도, 회상 카드, 학습 추천 기능은 없습니다.
- 채권·금리, 포트폴리오 상관, 복리·과세 시점, DCF 민감도, AD–AS, 비상자금의 여섯 가지 계산 도구를 제공합니다.
- 모바일 화면, 키보드 검색, 모션 감소 설정을 지원합니다. 인쇄본은 웹과 같은 본문에서 생성합니다.
- 증권시장 시뮬레이션 탭에서 여러 가상 종목과 참여자별 재산·위험감수·가격 대응·레버리지·뉴스·거래량·감정을 설정합니다. 체결 기반 차트와 직접 주문, 기업 이슈, 거시경제, 시장 안정장치의 상호작용을 관찰합니다.
- 참여자 표의 열 제목을 가리키거나 클릭하면 속성 설명을 봅니다. ‘속성·규칙’에서 항목별 작동 방식을 찾을 수 있으며, 전체 설명은 [시뮬레이션 속성·상호작용 문서](docs/simulation-reference.md)에 정리합니다.

북마크는 현재 브라우저의 localStorage에 저장됩니다. 로그인·기기 간 동기화는 없습니다. 저장이 제한된 브라우저에서는 현재 페이지 세션에서만 유지됩니다. 이전 버전의 메모와 복습 기록은 사용하지 않으며 기존 저장값은 덮어 지우지 않습니다.

새 개념은 JSON에 고유 ID를 지정해 추가합니다. `summary`는 사전 카드의 짧은 설명이며, `body` 배열은 본문 문단입니다. `formula`는 본문의 두 번째 문단 다음에 표시합니다. `related`에는 관련 개념 ID를, `sources`에는 출처 ID를 사용합니다. 이전 원고의 `cue`, `detail`, `example`, `trap`, `paths`는 편집 이력으로 보존하며 현재 본문 화면에 사용하지 않습니다.

새 실험은 `LABS` 목록, `labMarkup`, `mountLab`에 추가하고 개념의 `lab` 필드로 연결합니다. `scripts/author_content.py`는 최초 원고 생성 기록이므로 현재 JSON에 다시 실행하지 않습니다. 예전 `explorer`·`knowledge` 파일은 이전 작업 보존용이며 현재 화면에서 로드하지 않습니다.

## 자료와 계산의 범위

원고는 개념과 판단 구조를 설명합니다. 시점에 따라 달라지는 세율·공제 한도 등을 고정된 현재 값으로 제시하지 않고 법령과 공식 안내를 연결합니다. 각 계산 도구는 가정을 화면에 표시하며 실제 금융상품 수익이나 거시경제의 예측을 보장하지 않습니다.

## 시장 데이터

- 원·달러: Frankfurter v2의 ECB 자료, 일별 공시와 최근 30일 이력. 1시간 로컬 캐시.
- BTC·ETH: 업비트 공개 REST API, 화면이 보일 때 60초 간격 조회.
- 기준일·시세 시각·제공처를 표시합니다. 수동 새로고침은 캐시를 우회합니다.
- 요청이 실패하면 이전 저장값임을 표시하거나 조회 불가 상태를 안내합니다.
- 화면 이탈 시 요청과 갱신 타이머를 중단합니다. 북마크 등 개인 기록은 제공처에 전송하지 않습니다.

## 검증 및 배포

### 증권시장 시뮬레이션 v0.3.1

`#simulation`에서 기본 3개 가상 종목과 2~100명의 참여자를 설정하고 직접 주문을 낼 수 있습니다. 상승·하락 대응은 매수, 레버리지 매수, 수익실현, 손절/축소, 공매도, 초기 비중 유지, 관망입니다. 자동 참여자끼리는 교차한 지정가의 중간 가격으로, 직접 주문은 조건을 만족하는 상대 호가에서 체결합니다. 현금과 주식은 거래 상대에게 이동합니다. 거래 상대가 없으면 가격과 거래량을 만들어내지 않습니다. 초기 주식 수는 참여자의 초기 주식 배분으로 결정하며, 기존 주식의 대차를 단순화한 공매도와 차입을 허용합니다. 거래 현금의 이자 정산·세금·수수료·재무제표의 자동 갱신·환율·해외시장·별도 인버스/인덱스 상품은 포함하지 않습니다.

기본 구성은 6명이며 시작 주가 10,000원, 난수값 42입니다. 동일한 설정과 난수값은 실행 속도에 관계없이 같은 결과를 만듭니다. 적용한 설정만 별도의 `fieldbook-simulation-config-v1` 키에 저장합니다. 실행 결과는 탭 이동 동안 메모리에 유지되고 화면 이탈 시 정지하며, 새로고침하면 저장된 설정으로 새 실험을 시작합니다. 설정을 바꾸면 일시정지하고 명시적으로 적용해야 새 실험에 반영됩니다.

상단 종목 선택에서 필드테크(10,000원), 데일리생활(8,000원·경기방어주), 프라임산업(20,000원·경기순환주)을 전환합니다. 종목마다 차트·호가·재무정보·기업 유형·소식이 분리되며, 경제지표와 참여자 성향은 공통입니다. 회사 이름·시작가·재무·소식 설정은 선택한 종목만 수정합니다. 기존 저장 설정의 주 종목과 참여자는 보존하고 두 기본 종목을 보완합니다.

`SecuritiesSimulation`은 종목별 `MarketSimulation`을 같은 시계로 진행하며 참여자의 현금·차입·담보를 공유합니다. 초기 주식 비중과 절대 목표 비중을 종목 수로 나누므로 종목 추가로 재산이 복제되지 않습니다. 순자산·신용·총 보유·공매도 한도는 모든 종목을 합산합니다. 표시 순서대로 각 종목을 체결하므로 앞 종목의 거래는 뒤 종목의 주문 여력에 영향을 줄 수 있습니다. 참여자 결과의 순자산·현금은 전체 계좌, 보유 주식·최근 행동은 선택한 종목 기준입니다.

차트의 ‘직접 거래’에서 시장가·지정가, 수량, 매수·매도·공매도를 선택합니다. 정지 중 주문하면 가상 10초를 진행하고 실행 중에는 다음 틱에서 처리합니다. 시장가는 좋은 상대 호가부터 순서대로 체결하고 그 틱의 미체결 잔량을 취소합니다. 지정가는 가격 조건을 만족할 때만 체결하며 잔량은 직접 취소할 때까지 유지합니다. 종목당 내 대기 주문은 하나이고, 대기 주문은 다른 종목의 현금과 담보도 예약합니다. 매도는 보유 주식 내에서만 가능하며 공매도는 별도 선택해야 합니다.

내 초기 자금은 기본 1억원이며 ‘시장 설정 → 시장 기본’에서 변경합니다. 직접 거래의 차입 한도는 계좌 전체에 1~3배로 적용하고 실행 중 바꿀 수 있습니다. 신용 한도는 초기 자금 × (배수 − 1), 총 보유 한도는 현재 순자산 × 배수입니다. 공매도는 초기 자금과 현재 순자산 중 작은 금액의 75% 이내이며, 총 보유·종목 간 공통 담보 제한도 함께 적용합니다. 배수 변경 시 대기 주문을 취소하며, 담보 초과 시 다음 틱에 반대매매를 제출합니다. 반대매매에도 상대 주문이 필요합니다. 차입 선택으로 현금을 미리 만들어내지 않으며 실제 체결된 매수 금액이 현금을 넘을 때 차입금으로 표시합니다.

‘내 계좌’에는 전체 순자산·손익·현금·차입금과 종목별 보유량·평균단가·평가손익을 표시합니다. ‘참여자 반응’은 내 체결량·평균 가격·주문 전후 가격과 마지막 체결 다음 틱의 매수·매도·관망 인원, 참여자별 주문을 기록합니다. 주문 전후 가격에는 같은 틱의 다른 거래가 포함되며 반응에는 다른 가격·소식 조건도 작용합니다. 이를 주문만의 인과 효과나 수익률 보장으로 해석하지 않습니다. 새로고침·초기화·설정 적용은 계좌와 전체 종목을 함께 다시 시작합니다. 종목 구성은 `additionalCompanies`(추가 최대 5개), 계좌 초기값은 `player`, 직접 거래 화면은 `simulation-trading.js`에서 확장합니다.

‘속성별 비율로 구성’에서는 총인원(기본 20명)과 위험 회피·중립·선호, 재산 규모, 상승·하락 대응, 초기 주식 비중, 레버리지 한도별 참여자 비율을 설정합니다. 각 속성의 합계가 100%여야 적용되며 ‘합계 100%로 맞추기’로 입력한 가중치를 정규화할 수 있습니다. 비율은 인원 기준이며 자금 비중과 다릅니다. 총인원에 대한 몫의 정수 부분을 먼저 배분하고 나머지가 큰 항목부터 남은 인원을 배분합니다. 입력 비율과 환산된 실제 인원·비율을 함께 표시합니다. 예를 들어 20명 중 위험 선호 60%는 위험감수 85인 참여자 12명을 생성합니다. 위험 회피·중립 대표값은 각각 20과 50입니다. 다른 수치 속성도 화면에 표시한 대표값으로 생성하며, 각 속성을 별도의 난수 순서로 섞습니다.

‘설정 적용 · 새로 시작’은 입력한 비율로 실제 참여자를 생성해 엔진에 넘깁니다. 현재 시장의 위험감수 구성은 참여자 화면의 결과 표 위에서 확인합니다. 생성한 참여자는 ‘참여자별 설정’으로 전환해 개별 수정할 수 있으며, 이 경우 자동 생성 설정은 해제됩니다. 개별 설정은 한 행이 참여자 한 명인 편집표로 표시합니다. 화면 크기에 맞춰 행과 속성 열을 페이지로 넘기며, 다른 쪽의 수정도 유지됩니다. 비율 모드와 설정은 새로고침 후 복원됩니다.

참여자 편집표의 ‘전체’에는 2~100명을 입력합니다. ‘인원 배정’에서 위험감수·재산·행동·확률·소식 반응 등 속성별 그룹 인원을 지정한 뒤 ‘표 생성’을 누르면 실제 개별 참여자를 만듭니다. 빈 배정 칸은 기본 비중으로 남은 인원을 나눠 채웁니다. 예를 들어 총 20명 중 위험 선호형 10명과 고액 자산가 5명만 정하면 다른 속성과 나머지 인원은 자동으로 배정됩니다. 각 속성은 독립적으로 섞이며, 명시한 0명도 반영합니다. 전체를 초과하거나 모든 그룹을 지정했는데 합계가 맞지 않으면 생성을 차단합니다. 설정 적용 시 아직 생성하지 않은 유효한 배정도 반영합니다.

표의 이름·숫자·선택 항목을 직접 수정할 수 있습니다. 수동 셀은 파란색이며 인원을 다시 생성해도 같은 행의 수정값을 유지합니다. 값을 비우거나 선택 항목의 ‘자동’을 고르면 자동값으로 돌아가고, 행 끝의 ↺는 해당 행 전체를 자동 설정합니다. Enter와 Shift+Enter는 같은 열의 다음·이전 참여자로 이동합니다. 배정 영역을 접으면 더 많은 행을 표시하며 가로·세로 스크롤 대신 행·열 페이지를 사용합니다. 수동 수정은 배정 조건보다 우선하므로 그룹별 현재 인원과 배정 인원을 따로 표시하고, 대표값과 다른 확률 등은 별도 값 인원으로 집계합니다.

배정 조건과 수동 셀은 `participantPlan`에, 실제 엔진에 전달할 개별 객체는 `participants`에 저장합니다. 새로고침 시 저장한 객체를 재생성하지 않아 개별값을 보존합니다. 생성 규칙은 `simulation-roster.js`, 편집표는 `simulation-participants.js`에 분리했습니다. 새 속성을 `PARTICIPANT_ATTRIBUTES`에 추가하면 배정 목록·전체 속성 열·자동값과 검증에 함께 반영됩니다.

시뮬레이션 화면은 현재 창 높이에 맞춰 배치하며 ‘차트 / 거시경제 / 기업 정보 / 참여자 / 체결·분석 / 시장 설정 / 규칙’ 탭으로 전환합니다. 재생 제어는 어느 화면에서도 사용할 수 있습니다. 시장 설정은 ‘시장 기본 / 회사 재무 / 거시경제 / 기업 소식 / 시장 안정 / 참여자별 설정 / 속성별 비율’로 나눕니다. 참여자 결과·체결·속성별 비율·규칙은 스크롤 대신 이전·다음 버튼을 사용합니다. 모바일 결과는 참여자 카드로 표시합니다. 화면을 바꾸거나 창 크기를 조절해도 입력한 값과 실행 결과를 유지합니다.

참여자 결과의 이름 옆 ‘설정’으로 해당 참여자의 개별 설정을 엽니다. 편집표는 ‘전체 속성 / 재산·위험 / 상승 대응 / 하락 대응 / 기업 소식’으로 열을 골라 볼 수 있으며, 상승·하락 행동과 각각의 실행 확률(0~100%)을 별도로 입력합니다. 가상 10초마다 시드 기반 난수를 새로 뽑아 실행 확률과 비교합니다. 예를 들어 매도 80%는 난수가 0.8보다 작으면 매도 행동을 선택하고, 나머지 20%는 관망합니다. 매도 행동을 선택해도 자산·위험감수·호가·상대 주문에 따라 실제 주문량과 체결 여부가 결정됩니다. 반대매매는 확률을 적용하지 않습니다. 최근 행동에는 실행 확률·추첨 난수와 선택 결과를 표시합니다. 같은 설정과 난수값으로 초기화하면 동일한 결과가 재현됩니다.

참여자 편집표의 ‘거래량’ 묶음에서는 대응 성향·반응 확률(0~100%)·반응 강도(0~200%)·급증 기준(1.2~5배)을 지정합니다. ‘급증 시 추종’은 가격 방향을 따라 매수·매도하고 ‘과열 때 역행’은 반대로 행동합니다. ‘급증 시 보유 축소’는 매수·공매도 포지션을 줄이며 ‘저거래량 때 관망’은 거래량이 개인 급증 기준의 역수 이하이면 관망합니다. ‘거래량 무시’와 강도 0%는 기존 대응을 따릅니다. 새 속성도 성향별 인원·비율 배정과 개별 수정을 지원합니다. 기존 저장값에 빠진 거래량 항목은 추종·확률 70%·강도 100%·기준 2배로 보완합니다.

종목별로 실제 체결된 최근 6틱(1분)을, 그 앞 최대 30틱(5분)의 1분 평균과 비교합니다. 최소 12개의 거래 가능 틱과 양수인 이전 평균이 필요하며, 평균이 0이면 무한대 급증으로 취급하지 않습니다. 서킷브레이커 중단 시간은 관찰 구간에서 제외합니다. 현재 틱의 거래량은 다음 틱부터 판단에 사용하며 직접 거래의 체결도 포함합니다. 차트의 배수와 ‘체결·분석 → 시장 해석’에는 최근 1분 거래량·평소 1분 평균·배수·직전 틱 반응 및 주문 인원을 표시합니다. 공통 상태 배지는 2배 이상 급증·0.5배 이하 위축이며 각 참여자는 개인 기준으로 반응합니다.

매 틱 거래량 반응 확률을 시드 난수와 비교하고, 미반응이면 기존 가격 대응으로 돌아갑니다. 추종·역행은 가격 방향이 0이면 기존 대응을 유지합니다. 반응 강도와 급증 정도에 따라 목표 비중 및 한 번에 제출하는 주문 비중·호가 강도가 늘어나며, 기존 자금·담보·레버리지 한도를 적용합니다. 거래 중단·반대매매·안정장치·감정 행동과 반응한 기업 소식이 거래량보다 우선합니다. 거래량을 입력값으로 강제로 만들거나 주가를 직접 변경하지 않습니다. 비교 계산은 `calculateVolumeSignal`, 개인 판단은 `volumeOpinion`과 `decision`에 분리했습니다.

참여자 편집표의 ‘감정’에서는 감정 대응·평소 감정(0~100점)·감정 민감도(0~200%)·회복력(0~100%)·반응 확률(0~100%)·공포 기준(0~49점 이하)·탐욕 기준(51~100점 이상)을 설정합니다. 성향별 인원·비율 배정과 개별 수정을 함께 지원합니다. 기본값은 감정을 따르는 매매·평소 50점·민감도 100%·회복력 20%·반응 확률 70%·공포 25점·탐욕 75점이며 이전 저장값의 빠진 항목을 이 값으로 보완합니다.

감정 상태는 종목별로 누적됩니다. 이미 체결된 가격의 최근 1분 추세·직전 변화·최근 6분 고점 대비 하락, 실제 전체 계좌 손익, 직전 참여자 평균을 사용합니다. 손실은 같은 비율의 이익보다 크게 반영하고 거래량 급증은 가격 충격을 증폭합니다. 모든 참여자의 상태는 하나의 이전 평균을 기준으로 계산해 처리 순서에 따른 전염 차이를 피합니다. 회복력이 높을수록 평소 감정으로 빨리 돌아가며, 거래 중단 중에는 새 충격·전염을 멈추고 진정만 진행합니다. 현재 틱의 아직 발생하지 않은 체결이나 비공개 소식 내용은 미리 반영하지 않습니다. 계산은 `advanceEmotion`, 상태 갱신은 `updateEmotions`로 분리했습니다.

개인 감정이 기준에 닿으면 매 틱 `emotionOpinion`에서 감정 반응 확률로 추첨합니다. ‘공포 매도·탐욕 매수’는 공포에 보유 주식을 패닉셀로 줄이고 탐욕에 추격 매수합니다. 패닉셀은 새 공매도를 만들거나 기존 공매도를 늘리지 않습니다. ‘감정에 역행’은 공포에 매수·탐욕에 매도하고, ‘공포 때 관망’은 공포 구간에서 매매를 쉽니다. ‘감정 매매 안 함’·민감도 0%·반응 확률 0%는 감정 주문을 끕니다. 추첨에 실패하면 기존 소식·거래량·가격 대응을 따릅니다. 거래 중단·반대매매·안정장치가 감정보다 우선하며, 감정 반응은 기업 소식보다 우선합니다. 감정 주문도 기존 자금·담보·레버리지 한도 및 실제 상대 호가를 적용합니다.

차트의 ‘심리’ 버튼 또는 ‘체결·분석 → 시장 심리’에서 선택 종목 참여자의 단순 평균 공포·탐욕 지수, 개인 기준 도달 인원, 직전 감정 주문, 개인별 점수·행동을 봅니다. 0은 공포, 100은 탐욕인 자체 모형값입니다. 개인 이름을 누르면 해당 감정 설정 셀로 이동합니다. 목록은 화면 높이에 맞춰 페이지로 표시합니다. 감정 설정은 저장하지만 실행 중 감정 점수는 설정 적용·초기화·새로고침 때 평소 값으로 돌아갑니다.

비율로 생성한 참여자도 개별 수정할 수 있습니다. 결과에서 개별 설정을 열면 생성된 참여자를 그대로 복사해 수동 구성으로 전환하며, 나머지 참여자의 속성은 보존합니다. 새로 적용하기 전까지 현재 시장 결과는 유지됩니다. 실행 확률도 속성별 비율로 배분할 수 있습니다. 이전 개별 저장값에 확률 항목이 없으면 100%로 해석합니다.

‘기업 정보’에는 실적·재무상태·투자지표가 있습니다. ‘재무정보 수정’ 또는 ‘시장 설정 → 회사 재무’에서 연간 매출·영업이익·순이익, 자산·부채, 참조 PER와 재무정보 반영도를 입력합니다. 기본 가상값은 매출 10억원, 영업이익 1.2억원, 순이익 0.8억원, 자산 6억원, 부채 2억원입니다. 실제 기업 자료를 조회하지 않으며, 입력값은 실행 중 고정합니다. 재무 입력 정의는 `COMPANY_FINANCIAL_FIELDS`에 모았습니다.

자본은 자산 − 부채이며, 모형 주식 수는 참여자의 초기 보유 주식 합계입니다. 시가총액은 현재가 × 모형 주식 수, EPS·BPS는 각각 순이익·자본을 같은 주식 수로 나눈 값입니다. PER는 순이익이 양수일 때만, PBR·ROE·부채비율은 자본이 양수일 때만 표시합니다. ROE는 기말 자본을 사용한 단순 값입니다. 매출·자산·주식 수가 0인 경우 나눗셈 결과를 만들지 않고 상태를 표시합니다. 실시간 현재가에 따라 시가총액·PER·PBR이 함께 갱신됩니다.

재무 참조 주가는 흑자이면 EPS × 참조 PER, 손익이 0 이하이면 양수 BPS, 자본도 0 이하이면 0원입니다. 재무정보 반영도 `w`(0~1)를 사용한 지정가 판단 기준은 `max(1, 시작가 × (1 − w) + 재무 참조 주가 × w)`입니다. 모형 주식이 없으면 시작가를 사용합니다. 반영도 기본값 0%는 기존 판단을 유지하며, 설정을 높이면 재무정보가 주문 판단에 영향을 줍니다. 주가를 참조값으로 강제 이동시키거나 회사 이익을 거래 현금에 지급하지 않습니다. 설정 적용과 저장·초기화는 다른 시장 설정과 같습니다.

‘거시경제 → 지표 설정’에서 실질 GDP 성장률·소비자물가 상승률·기준금리·거시경제 반영도를 입력합니다. 기준·호황·침체·고물가의 시나리오 버튼도 제공합니다. 실제 국가의 통계를 조회하지 않으며, 중립 기준은 GDP 2%·물가 2%·금리 3%, 거시경제 반영도 기본값은 100%입니다. 지표는 고정된 연간 조건으로 사용하며 가상 10초마다 GDP를 누적하거나 분기 발표를 만들어내지 않습니다. GDP는 물가 변화를 구분한 실질 성장률을 사용합니다. [IMF의 실질 GDP 설명](https://www.imf.org/en/publications/fandd/issues/series/back-to-basics/gross-domestic-product-gdp)

‘거시경제 → 기업 유형’ 또는 ‘회사 재무 → 기업 유형’에서 현재 회사를 경기순환주·경기방어주·중립형으로 지정합니다. 유형과 민감도는 `companyProfile`에 저장하며 유형 선택 후 각 수치를 수정할 수 있습니다. 순환·방어 구분은 [MSCI 분류 개념](https://www.msci.com/eqb/methodology/meth_docs/MSCI_Cyclical_and_Defensive_Sectors_Indexes_Methodology_Nov22.pdf)을 참고했으며, 다음 계수는 이 앱에서 조정 가능한 모형 가정입니다.

| 기업 유형 | GDP 민감도 | 물가 비용 민감도 | 금리 민감도 |
| --- | ---: | ---: | ---: |
| 경기순환주 | 1.8 | 0.75 | 6 |
| 경기방어주 | 0.35 | 0.25 | 4 |
| 중립형 | 1 | 0.5 | 5 |

GDP 성장률의 중립 기준 대비 차이에 GDP 민감도를 곱해 매출 변화를 추정합니다. 기본 실적이 같고 물가·금리가 중립일 때 GDP 5%는 순환주의 매출을 5.4%, 방어주의 매출을 1.05% 늘리는 가정입니다. 침체에서는 같은 방식으로 순환주의 감소 폭이 더 크며 방어주가 자동으로 상승하지는 않습니다. 입력 실적과 별도로 ‘기업 정보 → 경기 영향’에 추정 매출·영업이익·순이익과 판단 기준 변화를 표시합니다.

추정식에서 영업비용 `C = max(0, 매출 − 영업이익)`의 70%를 변동비로 가정합니다. 거시 반영도 `w`에 대해 매출 배수 `R = 1 + w × (clamp(1 + GDP민감도 × (GDP − 2)/100, 0.1, 3) − 1)`이며, 이익 변화는 `max(0, 매출 − 0.7C) × (R − 1) − C × 물가민감도 × (물가 − 2)/100 × w`입니다. 이 변화를 영업이익과 순이익에 더합니다. 별도의 세금·이자 현금 지급이나 이익의 자본 전입은 계산하지 않습니다.

금리 조정 배수는 `1 + w × (clamp(exp(−금리민감도 × (금리 − 3)/100), 0.25, 2) − 1)`이며 추정 참조 PER에도 적용합니다. 이익 기준금액은 `max(abs(순이익), 매출 × 0.05, 0.01억원)`이고, 거시 평가 배수는 `clamp(clamp(1 + 이익변화/기준금액, 0.1, 3) × 금리조정배수, 0.1, 3)`입니다. 최종 지정가 판단 기준은 앞의 재무 혼합 기준에 거시 평가 배수를 곱한 뒤 1원 이상으로 제한합니다. 두 반영도는 독립적이며, 거시 반영도 0%는 모든 경기 조정을 제외합니다. 시장가격은 기존과 같이 실제 주문의 체결로 결정됩니다.

거시 입력 정의는 `MACRO_FIELDS`, 시나리오는 `MACRO_PRESETS`, 기업의 기본 유형과 개별 민감도 입력은 `COMPANY_CYCLE_TYPES`·`COMPANY_EXPOSURE_FIELDS`, 추정식은 `calculateEconomicScenario`에 모았습니다.

‘기업 정보 → 기업 소식’에서 회사 발표의 진행 상태를 확인하고 ‘소식 설정’에서 최대 20개를 등록합니다. 일정에는 시작 후 발표 시점, 발표 전 사전 기대 공개 시점, 발표 후 관심 기간을 분 단위로 입력합니다. 사전 기대 0분이면 소문 없이 발표합니다. 내용에는 제목과 기대·실제 발표의 가치 변화율(-30~30%)을 따로 입력합니다. 양수는 호재, 음수는 악재입니다. 신규 기본 구성에는 실적 개선, 계약 기대 후 악재, 소문 없는 생산 차질 예시가 있습니다. 기존 저장 구성에는 소식을 자동 추가하지 않으며 빈 소식 설정에서 예시 3개를 불러올 수 있습니다.

참여자의 ‘소식 대응’에서 선제 대응·발표 확인·반대 해석·소식 무시와 반응 확률을, ‘소식 세부’에서 강도(0~200%)와 지연(0~600초)을 설정합니다. 모든 소식 속성은 참여 인원 비율로도 배분할 수 있습니다. 선제 대응은 공개된 기대부터, 발표 확인은 확인된 실제 내용부터 판단하며 반대 해석은 받은 정보의 방향을 뒤집습니다. 반응 지연 동안은 아직 받지 못한 내용을 사용하지 않습니다. 반응 확률은 각 소식의 기대·내부정보·공개 발표 단계에 한 번씩 추첨하며 같은 단계에서는 결과를 유지합니다. 미반응·소식 무시·강도 0%는 기존 가격 대응을 따르고, 거래가 가능한 동안 반대매매는 소식보다 우선합니다.

소식의 가치 변화율은 해석의 크기이며 주가 수익률을 보장하지 않습니다. 선택된 단계의 변화율 × 반응 강도 × 방향에 발표 후 선형으로 줄어드는 관심 비중을 곱하고, 여러 소식의 합을 ±50%로 제한합니다. 뉴스 목표 주식 비중은 초기 비중 + 소식 해석 × (2 + 위험감수 비율 × 4)이며 차입·공매도 한도를 적용합니다. 이 목표를 현재 비중에 반복 가산하지 않으므로 기대보다 낮은 발표는 이미 늘린 보유량을 줄이는 계기가 될 수 있습니다. 지정가에도 받은 정보의 해석을 반영하지만 주가는 매수·매도 주문의 체결로만 바뀝니다. 재무제표나 참여자 현금을 자동 변경하지 않습니다.

미발표 실제 내용은 공개 정보만 받는 참여자의 판단과 공개 발표 값에 사용하지 않습니다. 사전 인지를 켠 이슈의 인지 대상자만 내부정보 전달 시점과 개인별 지연 이후 실제 내용을 먼저 사용합니다. 뉴스 추첨은 `seed + 참여자 ID + 소식 ID + 단계`로 분리한 난수 계열을 사용하므로 아직 정보를 받지 못한 참여자의 과거 판단에는 미래 결과가 섞이지 않습니다. 공개 발표 전에는 현황의 실제 내용도 ‘발표 전’으로 표시하며, 관찰자용 ‘인지 현황’에서 누가 실제 내용을 먼저 알고 있는지 구분합니다. 설정 정의는 `COMPANY_NEWS_FIELDS`, 검증은 `normalizeCompanyNews`, 정보 접근은 `informationFor`·`newsOpinion`·`publicNews`에 모았습니다.

차트의 ‘기업 이슈’ 버튼 또는 ‘기업 정보 → 기업 소식 → 이슈 발동’에서 실행 중 이슈를 추가할 수 있습니다. 실적 상향·대규모 계약·생산 차질·자금조달 부담 예시를 선택하거나 제목·가치 변화(-30~30%)·관심 기간을 직접 입력합니다. ‘발표·인지’에는 현재 시점부터 발표 대기(0~60분), 발표 전 내부정보 사용 여부, 전달 시점, 자동 배정 비율을 설정합니다. 대기 0분은 즉시 공개하며, 예정 이슈의 ‘지금 발표’는 기존 일정을 현재 시점으로 앞당깁니다. 일시정지 중 발동하면 매수 주문처럼 가상 10초를 진행해 첫 반응을 확인합니다. 시세·보유 자산·기존 봉·난수 진행은 유지하고 선택한 회사에만 추가합니다. 주가와 거래량은 여전히 실제 주문 체결로 결정됩니다.

개인별 ‘사전 인지’에는 ‘이슈 비율로 배정 / 사전 인지자 / 공개 정보만’이 있습니다. 이슈에서 ‘아무도 모름’을 선택하면 개인 역할과 관계없이 사전 인지를 끕니다. ‘일부 참여자 인지’는 명시적으로 지정한 인지자·공개 정보 참여자를 우선하고 자동 배정 인원 중 지정 비율을 반올림한 인원을 선택합니다. 예를 들어 자동 배정 10명 중 30%는 3명입니다. 배정 순서는 별도 시드 해시를 사용하며 이슈의 실제 내용과 독립적입니다. 같은 속성은 ‘속성별 비율 → 내부정보 접근’에서도 배분합니다. 기존 저장값의 접근 기본값은 자동 배정이고 기존 예정 이슈의 사전 인지는 기본적으로 꺼져 있습니다.

내부자는 공개된 기대 대신 실제 내용을 읽으며, 발표 확인형도 받은 내부정보에는 반응할 수 있습니다. 알고 있는 것과 거래하는 것은 분리합니다. 소식 무시·확률 미선택·강도 0%·사이드카·거래 중단은 기존 규칙대로 적용하며 개인별 반응 지연 때문에 인지 대상이어도 발표 전에 정보를 받지 못할 수 있습니다. ‘인지 현황’은 개인의 접근 정책, 실제 인지 단계, 수신 시각, 최근 행동을 2명씩 표시합니다. 직접 발동 이슈는 종목당 실험 중 30개까지 보관하며 설정 적용·초기화·새로고침 시 제거됩니다. 원래 저장한 예정 이슈는 유지됩니다. 실행 중 이슈와 정보 전달은 `MarketSimulation.newsEvents`, `triggerCompanyIssue`, `announceCompanyIssue`, `hasInsiderAccess`, 화면은 `simulation-issues.js`에서 관리합니다.

차트는 가상 10초 단위의 틱 6개를 1분봉으로 묶고 5분봉도 제공합니다. 현재 봉의 고저가와 거래량이 갱신되며, 20/60봉 이동평균, 마우스 십자선, 휠 확대, 드래그 이동, 방향키·+/−·Home을 지원합니다. 최근 1,200개 1분봉과 최근 40개 체결을 보관하며, 누적 거래량·고저가·최대 낙폭은 전체 실험 기준입니다. 최종 자산은 `현금 − 차입 + 보유 주식 × 현재가`이며 공매도는 음수 주식 수로 표시합니다. 신규 차입은 초기 재산 × (최대 레버리지 − 1), 공매도는 초기/현재 순자산 중 작은 금액의 10~75% 한도입니다. 평가 포지션이 순자산 × 최대 레버리지 × 1.12를 넘으면 축소 주문을 제출합니다. 포지션 청산은 허용하되 거래 상대가 필요하며 손실이 차입 한도를 넘을 수도 있습니다.

속성을 추가하려면 `simulation-engine.js`의 `PARTICIPANT_ATTRIBUTES`에 범위·기본값·입력 종류를 추가합니다. 설정 UI와 검증이 이 목록을 함께 사용합니다. 수치 속성의 `groups`에는 그룹별 `key`, `label`, `value`를, `distributionDefaults`에는 초기 비율을 지정하면 비율 편집기에도 나타납니다. 그룹을 지정하지 않으면 기본값 100%로 생성합니다. 행동은 `REACTIONS`에 `label`과 `target(context)`를 추가하면 개별·비율 선택 목록에 모두 나타납니다. 목표 비중에 판단 차이를 반영하려면 `noise: true`, 주식 수를 그대로 유지하려면 `keepShares: true`를 사용합니다. 다종목의 절대 목표 비중은 `allocationWeight`를 반영합니다. 여러 속성의 상호작용은 `new MarketSimulation(config, {decisionModifiers:[...]})`로 연결합니다. 공통 계좌와 종목별 정산 연결은 `simulation-exchange.js`에서 관리합니다.

소식 대응처럼 매매 행동과 별개인 선택 속성은 `type:'choice'`와 `options:[{key,label,note}]`로 정의합니다. 이 선택지는 개별 편집기·검증·비율 생성에 공통으로 사용됩니다.

‘체결·분석 → 시장 안정’에서 전체 종목 지수, 판단 참여 비율, 평균 주문 열기와 최근 60건의 발동·해제 기록을 확인합니다. 상단 상태 배지에서도 같은 화면을 열 수 있습니다. 지수는 종목별 `현재가 / 시작가`를 균등 평균한 뒤 100을 곱합니다. ‘시장 설정 → 시장 안정’은 사이드카 기준·효과, 서킷브레이커 기준, 중단·재개 시간으로 나누며 기존 설정 적용·저장·초기화와 연결됩니다. 이 장치는 실제 거래소의 선물·프로그램 매매 규정을 재현하는 대신 참여자의 행동을 조절하는 모형입니다.

사이드카 기본 조건은 최근 최대 1분의 지수 변화가 상승·하락 어느 쪽이든 5% 이상일 때 5분 발동하고 해제 후 5분 동안 재발동을 기다리는 것입니다. 발동 중 판단 참여 비율은 15%입니다. 기존 상승·하락 행동 확률과 별도의 시드 난수로 참여 여부를 추첨하므로 행동 확률 80%는 약 12%가 됩니다. 소식에 반응한 참여자도 이 참여 추첨을 거칩니다. 참여한 주문의 수량과 호가 강도도 15%로 줄입니다. 각 참여자의 주문 열기는 위험감수 수치 × 참여 비율이며 최근 판단과 함께 표시합니다. 반대매매와 직접 주문은 사이드카 감축에서 제외하지만, 거래 상대가 부족하면 체결되지 않을 수 있습니다.

서킷브레이커는 시작 지수 대비 8%·15%·20% 하락의 세 단계가 기본이며 각 단계는 실험당 한 번 발동합니다. 큰 폭의 하락은 상위 단계로 바로 진입합니다. 기본 중단 시간은 모든 단계에서 20분이며 이 연속 시뮬레이션에는 별도의 장 종료가 없습니다. 기준에 도달한 틱의 실제 체결은 유지하고 다음 틱부터 전체 종목의 체결·반대매매를 멈춥니다. 중단 중에는 새 직접 주문을 접수하지 않으며 기존 지정가 잔량과 예약 자금은 유지하고 취소는 허용합니다. 시간과 기업 발표는 진행하고 차트에는 가격이 유지되는 무거래 봉을 기록합니다.

사이드카 해제 후에는 참여·주문 강도가 발동 비율에서, 서킷브레이커 해제 후에는 25%에서 기본 3분 동안 100%로 선형 회복합니다. 회복 시간 0분은 즉시 정상화합니다. 장치가 겹치면 더 낮은 참여 비율을 적용하며 완전 중단이 우선합니다. 발동 기준·시간·참여 비율·재발동 대기·단계별 하락 기준은 모두 수정할 수 있습니다. ‘사이드카 시험 / 서킷브레이커 시험’은 가격이나 자산을 바꾸지 않고 장치만 발동시키며 이력에 시험 발동으로 기록합니다. 일시정지는 장치의 가상 시간도 멈춥니다. 같은 설정·난수와 같은 직접 주문·시험 발동 순서는 같은 결과를 만듭니다.
